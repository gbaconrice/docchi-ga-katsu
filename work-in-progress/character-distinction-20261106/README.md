## 現状の監査

全300種の実データ・比較画面の説明は `inventory.json`。現在の能力と次の確認優先度は `character-review-300.json`。

- 大型は46種。現行の大型化はHP5倍・与ダメージ3倍・射撃被ダメージ最大50%という共通補正を含む。大型固有の設計と共通倍率は分けて評価する必要がある。
- 特殊な挙動の有無で粗く整理すると70系統、単独所属41系統。68種は追跡した特殊能力フラグなし。これは「70種類しかない」「68種が完全同一」という意味ではない。攻撃の間合い、形状、予備動作、連撃の間隔、標的の取り方には別の差がある。
- 多い系統は通常近接、連撃、周囲攻撃、前方攻撃、回復、防護。既存の形状やタイミングだけで十分違うものと、同じ役割を重複しているものを分けて扱う。
- 特にフロストライノ、ファントムスケイルドラゴン、2種のゴーレム、重い単発攻撃だけの大型が最初の見直し対象。
- 召喚、蘇生、死亡爆発、弱点露出、毒、足止め、回復阻害、吸収、かばう、反射、引き寄せなどの既存経路は実在する。能力名だけを増やす必要はない。

### 自己修復3種

現行ではリペアピラー50%、エンバーグリルモニュメント75%、リペアエッグ150%の直接攻撃反射がある。従って「何もせず自己回復するだけ」ではない。ただし、全て同じ30回復×3回、0.6秒準備、2秒再使用で、主な差はHPと反射率。静止したまま相手に殴られることを待つ構造も共通する。

次は1種を耐久反射柱として残し、1種を被弾蓄積の一回放出、1種を割れた時の一体防護などへ分ける案を比較する。これらは**未実装案**であり、今回3種の挙動は変更していない。

## 初案を採用しなかった理由

最初は移動鈍足だけを実装したが、80戦で残HPの変化が0、戦闘時間の変化が4戦のみ、最大0.133秒だった。近接相手はすでに攻撃位置にいるため、移動だけ遅くしても効果が薄い。低HPの相手は元の102ダメージで倒れる。この初案を完成扱いしない。

既存の押し戻しと組み合わせる12/18/24px案を同じ80戦で比較した。全案で勝敗変更は0。残HP変化は12pxで27戦、18pxで28戦、24pxで26戦。最大戦闘時間差は順に3.08秒、2.4秒、2.95秒。単純に押す量を増やすほど有利にはならない。

18px案を局所候補とした理由は、最大24pxに頼らず、接触で距離を作り、その戻り足を鈍らせる役割が成立するため。既存の軽いプッシュアイの12pxより強いが、重量のあるロックゴーレムには18×400/2600 ≒ 2.77pxに軽減される。

## 最終候補の実効検証

20組の同額編成、予算6/12、2シード、左右反転で各ビルド80戦。地形は氷原と岩場。最終ファイルをそのまま使用し、実行時の能力上書きなし。

- 勝敗変更0、終了しない戦闘0、非有限値や生存中の不正HP0。
- 28戦で残HPが変化し、28戦で戦闘時間が変化。最大時間差2.4秒。
- 40戦で生存中の相手に氷角の効果が発生。
- 押し戻しイベント360回のうち、生存相手への押し戻し191回。残り169回は同じ攻撃で倒れた相手で、継続的な制圧効果として数えない。
- 鈍足89回。対象は盾兵24、リペアピラー8、ソーンバック29、クリスタルハンマーガード20、毒使い8。
- 対空不能な組み合わせの4引き分けは変更前後に共通。万能な大型にはしていない。

この標本は勝率の校正や全300種のバランス証明ではない。旧構成モデルの係数、生成結果、価格は変更せず、この種を変更済み能力に追加して「未校正」の表示を維持した。

## 検査した境界と表示

`candidate/tests/frost-rhino-identity.cjs` の25項目：

- 通常攻撃102と鈍足の時間・倍率・耐性。
- 再付与の非重複、免疫終了後の再付与、既存の足止め免疫との共有。
- 解除は次のtickから。解除後も耐性を維持。
- 完全受け流し、致死、かばう、敵味方、飛行、射撃、反射、同時死亡。
- 移動のみ遅くなり、攻撃タイマー自体は変えない。
- 18px移動、重量抵抗、壁、複数ライノの同時押し戻しの非重複。
- 比較欄に氷角の効果・解除・耐性と押し戻しを表示し、control色を使用。
- 実際の鈍足イベントが対象位置の既存 `frost_hit` 演出へ入ることを動的に確認。
- 同じ入力の再生一致、ログの未知イベント0、鈍足の表示フラグ、2個の新規メモリ内受信機への転送結果一致。切断途中からの復帰は未検査。

実サソリと同時に命中した場合は、既存の共有耐性仕様に従い最初に受理された足止めまたは鈍足だけが適用される。両優先順で双方の命中を確認した。弱い鈍足が先なら味方の足止めを妨げ得るため、編成上の相性として注意する。蘇生個体を作る既存関数で鈍足と耐性が消えることも確認した。この追加検査自体は戦闘内の完全な蘇生シーケンスではない。

全128スクリプト成功。全301レコード、大型46種、価格、人数、モデル、素材の保全検査を含む。履歴フィクスチャは上書きせず、フロストライノに追加する**5フィールドだけ**と近接処理の**1行だけ**を明示して除いた上で元のハッシュを照合し、その他の差分を許さない。現在のフィクスチャが今回の全バランスを保証するという意味ではない。

2本の既存ブラウザ専用スクリプトはNode全体実行から元来除外されている。再生転送のVM検査は、実ブラウザの見え方・実ネットワークの代わりにはならない。

## 段階的な残作業

`boss-proposals-46.md` に大型ごとの方向案を記録した。提案を実装済みとは扱わない。

1. 大型46種から、既存の形状だけでは説明しにくい数種を優先。攻撃条件、対象選択、予告、破り方が異なる小変更に分ける。
2. 自己修復3種、回復14種、防護8種などの支援役を整理。回復量違いだけでなく、防ぐ対象・発動の機会・有限回数を分ける。
3. 一般近接と連撃の大群を整理。全員に状態異常を足すのではなく、後退、対空、召喚体対策、強化解除、初撃限定など、編成に意味のある役割を割り当てる。
4. 各変更で同額比較、役割が刺さる相手と苦手相手、タイムアウト、解除、死亡・蘇生、容量、ログ、再生を再検査。
5. 能力追加後のモデル再校正と実機表示検証は別途必要。大型を複数増やしたり召喚数で強さを作ったりする案は今回追加していない。

## 再現と統合

- 入力は main のリダイレクト `index.html` ではなく、再構成済みのゲーム本体HTML。SHA検査が違う入力への適用を拒否する。
- `python rebuild-frost-rhino.py BASELINE_HTML OUTPUT_HTML` でHTMLを再現。出力先は独立した候補へ。
- `frost-horn-source-and-tests.patch` は再構成元からのコード・試験差分。対象は公開エントリではない。
- `candidate/` は検証したゲーム本体と試験一式。`FROST_RHINO_CANDIDATE.json` と `INTEGRATION_CANDIDATE_MANIFEST.json` がこの候補の識別子。コピー元の旧レポートは履歴資料。
- 統合する場合は、main の外部公開ビルド手順にこの再構成後の局所差分を組み込み、公開assetと入口を別途生成・検証する。今回その工程や公開は行っていない。
